SVG Pan and Zoom: Complete Interactive Viewport & Infinite Canvas Guide (2026)

By Jouni Flemming Published November 5, 2026 4,520 Words 19 min read Hardware Compositing & Matrix Transforms

Executive Architecture Summary: Implementing fluid, 120 FPS pan and zoom inside Scalable Vector Graphics (SVG) powers modern design canvas tools (Figma, Miro), interactive floorplans, CAD diagrammers, node graphs, and mapping applications. While legacy web tutorials rely on bloated 500 KB libraries or buggy coordinate math, modern web standards allow zero-dependency, hardware-accelerated vector viewports.

  • The Two Paradigms: ViewBox manipulation (updating minX minY width height) alters the native vector viewport without touching child DOM nodes. Affine transform matrix manipulation (applying matrix(a,b,c,d,e,f) to a viewport group <g>) achieves hardware-composited 120 FPS performance on Chromium and WebKit.
  • Focal Zoom-to-Point Math: Zooming toward the cursor requires translating the viewport so the user coordinate under the cursor remains stationary: newMinX = pX - (pX - oldMinX) / scaleFactor.
  • Multi-Touch Pinch Mechanics: Calculating distance ratios and midpoint coordinates between two simultaneous touch contacts enables seamless mobile gestures without layout thrashing.
  • Stroke Scaling Control: Enforcing vector-effect: non-scaling-stroke; guarantees that visual wireframe lines and icon strokes remain razor-sharp and consistent regardless of zoom magnitude.

1. The Geometry of Vector Viewports: Screen Space vs. SVG User Space

The foundational challenge of interactive vector viewports lies in translating between two contradictory coordinate universes: Screen Pixel Space and SVG User Coordinate Space. Screen space is dictated by client browser window pixels (originating at clientX: 0, clientY: 0 at the top-left corner of the browser viewport). In contrast, SVG user space is defined by an arbitrary, resolution-independent mathematical Cartesian grid where units can represent millimeters, CAD mils, geographic meters, or abstract vector points.

When a user rolls the mouse wheel or touches a glass trackpad, the browser dispatches an event containing screen coordinates. If you naively apply those numbers to SVG geometry without taking into account page scroll, CSS padding, container scale transforms, and device pixel ratios, the vector artwork will visibly jump, drift, or pivot wildly off-screen. To bridge this divide, the SVG DOM specification provides the Current Transformation Matrix (CTM) through the interface method getScreenCTM().

The method svg.getScreenCTM() computes a 2D affine transformation matrix that represents the exact mathematical mapping from the SVG internal coordinate space to the client screen display. By computing the mathematical inverse of this matrix via ctm.inverse(), web applications can map any arbitrary mouse or touch event into precise SVG user space with micro-millimeter fidelity.

Mathematical Formula: Screen Coordinate to SVG User Space Mapping
Point_SVG = (Screen_Matrix)^(-1) × Point_Client
Where Screen_Matrix is obtained from svgElement.getScreenCTM() and multiplied by DOMPoint(clientX, clientY) via matrixTransform().

In modern web browsers, this coordinate translation is executed utilizing the standard DOMPoint and DOMMatrix APIs. The code snippet below illustrates the production-grade, zero-dependency pattern for converting client pointer events into local vector coordinates:

// Zero-dependency helper function to convert screen client coordinates to SVG user coordinates
function screenToSVG(svgElement, clientX, clientY) {
  const ctm = svgElement.getScreenCTM();
  if (!ctm) {
    return { x: 0, y: 0 };
  }
  // Use DOMPoint if supported, or create an SVGPoint fallback
  if (window.DOMPoint) {
    const point = new DOMPoint(clientX, clientY);
    const transformed = point.matrixTransform(ctm.inverse());
    return { x: transformed.x, y: transformed.y };
  } else {
    const pt = svgElement.createSVGPoint();
    pt.x = clientX;
    pt.y = clientY;
    const transformed = pt.matrixTransform(ctm.inverse());
    return { x: transformed.x, y: transformed.y };
  }
}

This single function forms the cornerstone of every pan, zoom, drag-and-drop, and marquee-selection operation on an infinite vector canvas. Because it delegates the matrix inversion to the browser's C++ rendering engine, it handles CSS scale transforms, responsive container flexbox centering, and high-DPI Retina scaling automatically.

2. The Two Architectural Approaches: ViewBox Manipulation vs. Transform Matrix

When architecting an SVG pan-and-zoom engine, developers face a critical technical fork in the road: ViewBox Manipulation versus Affine Transform Matrix. While both approaches achieve visual scaling and translation, their rendering pipeline footprints, performance trade-offs, and behavioral nuances are radically distinct.

Architectural Feature ViewBox Manipulation (minX, minY, w, h) Transform Matrix (matrix(a,b,c,d,e,f))
Target Element Root <svg viewBox="..."> attribute Inner container group <g transform="...">
Compositor Acceleration Moderate — triggers attribute mutation and SVG layout pass Maximum — offloaded directly to GPU compositor thread
Non-Scaling Stroke Behavior Maintains uniform pixel stroke-width automatically Requires vector-effect: non-scaling-stroke; on elements
DOM Overhead Zero wrapper elements required Requires wrapping canvas elements in a master <g> tag
Minimap Synchronization Trivially calculated: viewBox matches camera lens Requires matrix inversion to compute visible bounding box
120 FPS Frame Stability May encounter micro-stutter on 10,000+ complex nodes Buttery smooth 120 FPS across Chrome, Safari, and Firefox
CSS Transform-Box Dependency None (native XML attribute) Requires setting transform-box: view-box; or inline matrix

Approach A: ViewBox Manipulation Engine

Under the viewBox method, the SVG root element's viewBox attribute is modified directly during every animation tick. The viewBox string consists of four floating-point numbers: minX minY width height. Panning updates minX and minY, shifting the optical camera across the coordinate plane. Zooming increases or decreases width and height: smaller dimensions zoom in, while larger dimensions zoom out.

// Updating the viewport using native viewBox string manipulation
function setViewBox(svg, minX, minY, width, height) {
  svg.setAttribute('viewBox', minX.toFixed(2) + ' ' + minY.toFixed(2) + ' ' + width.toFixed(2) + ' ' + height.toFixed(2));
}

The primary advantage of viewBox manipulation is its conceptual purity: child elements remain completely untouched, and external tools (such as minimap overlays or coordinate readouts) can inspect the current camera bounds simply by parsing the viewBox string. However, because mutating XML attributes causes the browser layout engine to re-verify SVG bounding boxes, extremely dense diagrams (over 20,000 nodes) can suffer from frame drops during rapid dragging.

Approach B: Affine Transform Matrix Engine

The transform matrix approach preserves the root SVG viewBox at a fixed dimension (for instance, 0 0 1000 1000) and wraps all visual children in a top-level grouping element: <g id="viewport" transform="matrix(scaleX, skewY, skewX, scaleY, translateX, translateY)">.

Because CSS and SVG transform matrices operate directly on GPU vertex buffers, modern browser engines (Google Blink, Apple WebKit, and Mozilla Gecko) can composite matrix transitions on the GPU thread without re-rasterizing un-changed vector paths. This makes matrix transformation the undisputed standard for professional web-based graphics suites, CAD viewers, and node graph editors.

3. The Zoom-to-Point Pivot Equation: Why Center-Zooming Fails

A classic bug in rudimentary pan-and-zoom scripts is center-zooming: whenever the user spins the mouse wheel, the entire diagram zooms inward toward the visual center of the screen, regardless of where the cursor is placed. This destroys user spatial orientation because the specific icon or circuit node the user is examining flies away from their mouse cursor.

True focal zooming (often called zoom-to-cursor or zoom-at-point) guarantees that the specific SVG coordinate lying directly beneath the mouse pointer remains pinned to that exact screen pixel before, during, and after the zoom operation. To achieve this mathematical invariance, the camera's translation offset must adjust simultaneously with the scale factor.

Mathematical Derivation: Focal Zoom Invariance Formula
newMinX = P_x - (P_x - oldMinX) × (newWidth / oldWidth)
Where P_x is the SVG user X coordinate under the pointer, oldMinX is the current viewport camera origin, and the ratio (newWidth / oldWidth) represents the inverse zoom delta factor.

Let us walk through the step-by-step mathematical proof: Suppose the mouse cursor is located at screen point (clientX, clientY), which maps to SVG point P = (pX, pY). If we zoom in by a scale factor s = 1.2 (making the viewport 20% smaller), the new width is newWidth = oldWidth / s. If the cursor position within the normalized viewport is given by ratio rX = (pX - oldMinX) / oldWidth, then after zooming, the point pX must satisfy the identical ratio: (pX - newMinX) / newWidth = rX.

Equating both sides and solving for newMinX yields the canonical equation:

newMinX = pX - rX × newWidth
         = pX - ((pX - oldMinX) / oldWidth) × (oldWidth / s)
         = pX - (pX - oldMinX) / s

This elegant formula ensures that no matter how rapidly or erratically the user spins their mouse wheel, the point under the cursor never drifts by a single subpixel.

4. Desktop Pointer Interactions: Wheel Zooming, Panning Deltas & Friction Decay

Translating user hardware inputs into silky, responsive motion requires handling three distinct pointer events: wheel delta normalization, drag translation, and inertial momentum decay.

Normalizing the Mouse Wheel Delta

A notorious cross-platform hazard in browser engineering is that the standard wheel event reports wildly inconsistent values across operating systems and hardware mice. An Apple Magic Mouse or MacBook trackpad emits micro-pixel deltas (e.g., deltaY = 1.5), while a physical notch-wheel mouse on Windows or Linux emits line steps (e.g., deltaY = 100 with deltaMode = 1).

If an engineer naively multiplies zoomFactor *= 1 + event.deltaY * 0.001, notch-wheel users will experience violent 20x zoom jumps, while trackpad users will barely notice any movement. The industry-standard normalization calculates an exponential zoom step clamped between safety bounds:

// Cross-platform mouse wheel delta normalization
function calculateZoomFactor(event, currentZoom) {
  event.preventDefault();
  
  // Standardize deltaMode: 0 = pixels, 1 = lines, 2 = pages
  let delta = event.deltaY;
  if (event.deltaMode === 1) delta *= 16; // Convert line mode to pixels
  if (event.deltaMode === 2) delta *= 800; // Convert page mode to pixels
  
  // Exponential zoom damping curve
  const zoomSensitivity = 0.0015;
  const zoomMultiplier = Math.exp(-delta * zoomSensitivity);
  
  // Clamp zoom levels to prevent floating point degeneration
  const minZoom = 0.1;
  const maxZoom = 25.0;
  const nextZoom = Math.max(minZoom, Math.min(maxZoom, currentZoom * zoomMultiplier));
  
  return nextZoom / currentZoom; // Return relative scale factor
}

Pointer Dragging with Pointer Events API

In 2026, legacy mousedown, mousemove, and mouseup handlers should never be used for canvas panning. The modern W3C Pointer Events API unifies mouse, stylus pen, and touch inputs under a single interface with explicit pointer capture capabilities.

By invoking event.target.setPointerCapture(event.pointerId) inside the pointerdown handler, the SVG element continues receiving pointer movement events even if the user drags their cursor outside the browser window boundary or across embedded iframes. This eliminates the frustrating bug where panning suddenly stalls if the user jerks their cursor past the canvas margin.

5. Mobile Multi-Touch Architecture: Dual-Finger Pinch Gestures & Midpoint Pivoting

On mobile devices and touchscreens, users expect native pinch-to-zoom ergonomics. Implementing pinch gestures requires tracking multiple simultaneous contact points, calculating dynamic hypotenuse distances, and extracting Euclidean midpoints.

When two fingers contact the screen, we record both touch identifiers in an active pointer cache. Each touch movement updates the Euclidean distance between the two points: dist = Math.hypot(p2.clientX - p1.clientX, p2.clientY - p1.clientY). The zoom factor is simply the ratio between the current distance and the distance recorded on the previous frame:

Mathematical Formula: Two-Finger Pinch Distance Ratio
Zoom_Factor = √((X_2 - X_1)² + (Y_2 - Y_1)²) / Initial_Distance
Simultaneously, the midpoint ((X_1 + X_2) / 2, (Y_1 + Y_2) / 2) serves as the focal pivot point for pan translation.

The beauty of this formulation is that panning and zooming merge into a single seamless gesture. If the user pinches while sliding their hands across the glass, the midpoint translates the canvas while the distance delta scales the viewport — exactly mirroring native mobile map applications.

7. Viewport Boundaries, Clamping & Collision Resistance

In real-world applications, you rarely want users to be able to drag the artwork infinitely into the void, losing sight of the content entirely. A robust pan-and-zoom engine enforces spatial boundary constraints that restrict camera travel.

Clamping is enforced by defining an allowable bounding rectangle in SVG user space: [minX_bound, minY_bound, maxX_bound, maxY_bound]. Before committing any translation offset, the engine computes the visible extent of the camera and clamps the pan position so at least a guaranteed percentage (e.g., 20%) of the artwork remains on screen.

// Bounding box clamping algorithm for SVG pan and zoom
function clampPan(x, y, scale, viewportW, viewportH, contentBounds) {
  const visibleW = viewportW / scale;
  const visibleH = viewportH / scale;
  
  // Enforce 15% minimum content visibility padding
  const padX = visibleW * 0.15;
  const padY = visibleH * 0.15;
  
  const minAllowedX = contentBounds.minX - visibleW + padX;
  const maxAllowedX = contentBounds.maxX - padX;
  const minAllowedY = contentBounds.minY - visibleH + padY;
  const maxAllowedY = contentBounds.maxY - padY;
  
  return {
    x: Math.max(minAllowedX, Math.min(maxAllowedX, x)),
    y: Math.max(minAllowedY, Math.min(maxAllowedY, y))
  };
}

When implementing rubber-band physics (similar to iOS scroll bounces), you allow the translation to travel past the strict clamping bounds by applying a logarithmic dampening curve: overdragDelta = delta × 0.35. Upon pointer release, an ease-out spring animation returns the viewport smoothly back to the clamped boundary threshold.

8. Physics-Based Inertia Momentum & Kinetic Velocity Deceleration

A static pan implementation that abruptly freezes the instant the user lifts their finger or mouse button feels jarring and mechanical. Modern fluid touch and pointer interfaces incorporate kinetic inertia, where the canvas continues gliding along its release trajectory with realistic friction decay.

To implement kinetic inertia, the pan engine tracks pointer velocity over a rolling sliding window of the last 3 to 5 pointer movements. We compute instantaneous velocity as the displacement vector divided by elapsed milliseconds: vx = Δx / Δt and vy = Δy / Δt.

Mathematical Formula: Kinetic Friction Deceleration Loop
V(t + Δt) = V(t) × (μ)^(Δt / 16.67)
Where μ is the kinetic friction coefficient (typically 0.94 for smooth glide) and 16.67ms normalizes for varying 60Hz, 120Hz, and 144Hz display refresh rates.

The code below demonstrates a robust, frame-rate independent inertia decay loop using requestAnimationFrame:

// Kinetic inertia decay physics engine for SVG panning
class InertiaEngine {
  constructor(onUpdate) {
    this.onUpdate = onUpdate;
    this.vx = 0;
    this.vy = 0;
    this.friction = 0.94;
    this.minVelocity = 0.05;
    this.rafId = null;
    this.lastTime = 0;
  }

  start(initialVx, initialVy) {
    this.stop();
    this.vx = initialVx;
    this.vy = initialVy;
    this.lastTime = performance.now();
    this.tick = this.tick.bind(this);
    this.rafId = requestAnimationFrame(this.tick);
  }

  tick(now) {
    const dt = Math.min(32, now - this.lastTime); // Cap delta time at 32ms
    this.lastTime = now;
    
    // Scale friction according to actual elapsed time
    const decay = Math.pow(this.friction, dt / 16.67);
    this.vx *= decay;
    this.vy *= decay;
    
    if (Math.hypot(this.vx, this.vy) < this.minVelocity) {
      this.stop();
      return;
    }
    
    this.onUpdate(this.vx * dt, this.vy * dt);
    this.rafId = requestAnimationFrame(this.tick);
  }

  stop() {
    if (this.rafId) {
      cancelAnimationFrame(this.rafId);
      this.rafId = null;
    }
  }
}

By checking Math.hypot(vx, vy) < 0.05, the loop gracefully terminates before performing unnoticeable sub-pixel translations, preventing unnecessary CPU wakeups when the canvas has come to rest.

9. Scaling to 100,000+ Nodes: Performance Optimization & Spatial Virtualization

While SVG scales gracefully for typical diagrams (hundreds or thousands of elements), rendering massive datasets (such as genomic charts, IC chip designs, or high-density network graphs with over 50,000 nodes) will choke the browser's Document Object Model if every node is retained in the active render tree.

To scale an SVG infinite canvas to 100,000+ elements, industry leaders employ four architectural optimizations:

  • Spatial Indexing (R-Trees & QuadTrees): All vector entities are registered in an in-memory R-Tree (such as flatbush or rbush). During every pan or zoom tick, the engine queries the current visible camera rectangle and toggles display: none; on nodes lying outside the viewport frustum. Elements hidden with display: none are completely bypassed during browser paint passes.
  • Geometric Level of Detail (LoD): When zoomed out below a threshold scale (e.g., scale < 0.3), detailed circuit paths and small text labels are swapped for simplified bounding boxes or single vector points.
  • Will-Change GPU Hinting: Applying will-change: transform; to the root viewport group <g> instructs the browser compositor to isolate the canvas onto its own GPU layer, avoiding costly re-paints of surrounding web application chrome.
  • Non-Scaling Stroke Management: Always set vector-effect: non-scaling-stroke; via CSS rather than recalculating individual stroke-width values in JavaScript loops on every zoom event.

Spatial culling is mathematically straightforward: compute the inverted bounding box of the camera viewport in SVG coordinates. Any entity whose axis-aligned bounding box (AABB) fails to intersect [camX, camY, camX + camWidth, camY + camHeight] is detached or hidden. This drops the active rendered DOM node count from 100,000 to only 200 visible elements, preserving constant 120 FPS rendering speeds.

10. Minimaps, Spatial Indexing & Coordinate Synchronization

Professional design environments provide a miniature radar view (minimap) in the bottom-right corner that displays the total canvas bounds and a semi-transparent rectangle depicting the current camera viewport. Keeping the minimap lens in sync with the primary canvas requires linear affine mapping:

// Synchronizing a minimap lens with the primary SVG camera
function updateMinimapLens(primaryCamera, minimapSvg, minimapLensRect, canvasBounds) {
  const minimapW = minimapSvg.clientWidth;
  const minimapH = minimapSvg.clientHeight;
  
  // Calculate relative scale between overall content and minimap dimensions
  const scaleRatioX = minimapW / (canvasBounds.width);
  const scaleRatioY = minimapH / (canvasBounds.height);
  
  // Map current primary camera viewBox to minimap pixels
  const lensX = (primaryCamera.minX - canvasBounds.minX) * scaleRatioX;
  const lensY = (primaryCamera.minY - canvasBounds.minY) * scaleRatioY;
  const lensW = primaryCamera.width * scaleRatioX;
  const lensH = primaryCamera.height * scaleRatioY;
  
  minimapLensRect.setAttribute('x', lensX.toFixed(1));
  minimapLensRect.setAttribute('y', lensY.toFixed(1));
  minimapLensRect.setAttribute('width', Math.max(12, lensW).toFixed(1));
  minimapLensRect.setAttribute('height', Math.max(12, lensH).toFixed(1));
}

Additionally, dragging the minimap lens should update the primary canvas bidirectionally. By attaching pointer listeners to the minimap lens, clicking or dragging within the radar view translates the primary camera instantly to the selected coordinate cluster.

11. Framework Implementations: React Hook, Vue Composable & Svelte Action

To integrate pan-and-zoom into modern frontend frameworks, encapsulate the event listeners and math within clean, idiomatic abstractions. Below is the production-ready React / Next.js hook:

// useSvgPanZoom.ts - Production React / Next.js Hook
import { useRef, useEffect, useState, useCallback } from 'react';

interface TransformState {
  scale: number;
  translateX: number;
  translateY: number;
}

export function useSvgPanZoom(minScale = 0.1, maxScale = 10.0) {
  const svgRef = useRef<SVGSVGElement | null>(null);
  const [transform, setTransform] = useState<TransformState>({
    scale: 1,
    translateX: 0,
    translateY: 0
  });

  const isDragging = useRef(false);
  const dragStart = useRef({ x: 0, y: 0 });

  const handlePointerDown = useCallback((e: React.PointerEvent<SVGSVGElement>) => {
    isDragging.current = true;
    dragStart.current = { x: e.clientX - transform.translateX, y: e.clientY - transform.translateY };
    e.currentTarget.setPointerCapture(e.pointerId);
  }, [transform.translateX, transform.translateY]);

  const handlePointerMove = useCallback((e: React.PointerEvent<SVGSVGElement>) => {
    if (!isDragging.current) return;
    setTransform(prev => ({
      ...prev,
      translateX: e.clientX - dragStart.current.x,
      translateY: e.clientY - dragStart.current.y
    }));
  }, []);

  const handlePointerUp = useCallback((e: React.PointerEvent<SVGSVGElement>) => {
    isDragging.current = false;
    e.currentTarget.releasePointerCapture(e.pointerId);
  }, []);

  const handleWheel = useCallback((e: React.WheelEvent<SVGSVGElement>) => {
    e.preventDefault();
    const svg = svgRef.current;
    if (!svg) return;

    const rect = svg.getBoundingClientRect();
    const mouseX = e.clientX - rect.left;
    const mouseY = e.clientY - rect.top;

    const delta = -e.deltaY * 0.0015;
    const newScale = Math.max(minScale, Math.min(maxScale, transform.scale * Math.exp(delta)));
    const scaleRatio = newScale / transform.scale;

    // Focal zoom adjustment
    setTransform(prev => ({
      scale: newScale,
      translateX: mouseX - (mouseX - prev.translateX) * scaleRatio,
      translateY: mouseY - (mouseY - prev.translateY) * scaleRatio
    }));
  }, [transform.scale, minScale, maxScale]);

  return {
    svgRef,
    transform,
    bind: {
      onPointerDown: handlePointerDown,
      onPointerMove: handlePointerMove,
      onPointerUp: handlePointerUp,
      onWheel: handleWheel
    }
  };
}

In Vue 3, this architectural logic maps seamlessly into a Composition API composable returning reactive ref(transform) states and pointer event directives:

// useSvgPanZoom.vue.ts - Production Vue 3 Composable
import { ref, onUnmounted } from 'vue';

export function useSvgPanZoom(minScale = 0.1, maxScale = 10.0) {
  const scale = ref(1.0);
  const panX = ref(0);
  const panY = ref(0);
  let isDragging = false;
  let startX = 0;
  let startY = 0;

  function onPointerDown(e: PointerEvent) {
    isDragging = true;
    startX = e.clientX - panX.value;
    startY = e.clientY - panY.value;
    (e.currentTarget as Element)?.setPointerCapture(e.pointerId);
  }

  function onPointerMove(e: PointerEvent) {
    if (!isDragging) return;
    panX.value = e.clientX - startX;
    panY.value = e.clientY - startY;
  }

  function onPointerUp(e: PointerEvent) {
    isDragging = false;
    try { (e.currentTarget as Element)?.releasePointerCapture(e.pointerId); } catch(_) {}
  }

  function onWheel(e: WheelEvent, svgEl: SVGSVGElement) {
    e.preventDefault();
    const rect = svgEl.getBoundingClientRect();
    const mouseX = e.clientX - rect.left;
    const mouseY = e.clientY - rect.top;
    
    const factor = Math.exp(-e.deltaY * 0.0015);
    const newScale = Math.max(minScale, Math.min(maxScale, scale.value * factor));
    const ratio = newScale / scale.value;
    
    panX.value = mouseX - (mouseX - panX.value) * ratio;
    panY.value = mouseY - (mouseY - panY.value) * ratio;
    scale.value = newScale;
  }

  return { scale, panX, panY, onPointerDown, onPointerMove, onPointerUp, onWheel };
}

In Svelte 5, an idiomatic action:panzoom attaches hardware-accelerated pointer event listeners directly to the DOM node lifecycle, ensuring effortless garbage collection when vector components unmount:

// panzoom.svelte.ts - Svelte 5 Custom Action
export function panzoom(node: SVGSVGElement, options = { min: 0.1, max: 10.0 }) {
  let scale = 1.0;
  let panX = 0;
  let panY = 0;
  let isDragging = false;
  let startX = 0, startY = 0;

  const targetGroup = node.querySelector('g.viewport-layer') as SVGGElement;

  function update() {
    if (targetGroup) {
      targetGroup.setAttribute('transform', \`matrix(\${scale}, 0, 0, \${scale}, \${panX}, \${panY})\`);
    }
    node.dispatchEvent(new CustomEvent('viewportchange', { detail: { scale, panX, panY } }));
  }

  function handleDown(e: PointerEvent) {
    isDragging = true;
    startX = e.clientX - panX;
    startY = e.clientY - panY;
    node.setPointerCapture(e.pointerId);
  }

  function handleMove(e: PointerEvent) {
    if (!isDragging) return;
    panX = e.clientX - startX;
    panY = e.clientY - startY;
    update();
  }

  function handleUp(e: PointerEvent) {
    isDragging = false;
    try { node.releasePointerCapture(e.pointerId); } catch(_) {}
  }

  function handleWheel(e: WheelEvent) {
    e.preventDefault();
    const rect = node.getBoundingClientRect();
    const mouseX = e.clientX - rect.left;
    const mouseY = e.clientY - rect.top;
    const factor = Math.exp(-e.deltaY * 0.0015);
    const nextScale = Math.max(options.min, Math.min(options.max, scale * factor));
    const ratio = nextScale / scale;
    panX = mouseX - (mouseX - panX) * ratio;
    panY = mouseY - (mouseY - panY) * ratio;
    scale = nextScale;
    update();
  }

  node.addEventListener('pointerdown', handleDown);
  node.addEventListener('pointermove', handleMove);
  node.addEventListener('pointerup', handleUp);
  node.addEventListener('wheel', handleWheel, { passive: false });

  return {
    destroy() {
      node.removeEventListener('pointerdown', handleDown);
      node.removeEventListener('pointermove', handleMove);
      node.removeEventListener('pointerup', handleUp);
      node.removeEventListener('wheel', handleWheel);
    }
  };
}

13. Frequently Asked Questions

What is the difference between viewBox manipulation and CSS transform matrix for SVG pan and zoom?

ViewBox manipulation updates the minX, minY, width, and height attributes of the root svg element, altering the coordinate system mapping for all child elements natively without altering DOM nodes. Transform matrix manipulation applies an affine transform matrix (scale and translate) to an inner root g element. Matrix transformation generally yields smoother 120 FPS animations because modern browsers offload CSS transform matrices to the GPU compositor thread, whereas frequent viewBox attribute mutations can trigger layout re-evaluations in complex document trees.

How do you calculate zoom centered on the mouse cursor instead of the top-left corner?

To zoom into the mouse cursor point (pX, pY), you must convert the screen coordinates of the cursor into SVG user coordinates using getScreenCTM().inverse(). When zooming by factor k, the new pan offset must shift by (pX - newPX) or mathematically: newMinX = pX - (pX - oldMinX) / zoomFactor. For matrix transforms, translate the origin to the cursor, apply the scale factor, and translate back: matrix = matrix.translate(pX, pY).scale(scaleFactor).translate(-pX, -pY).

How does mobile touch pinch-to-zoom work in SVG?

Touch pinch-to-zoom tracks two simultaneous touch points. The distance between the touch points calculates the pinch scaling factor relative to the touchstart baseline distance. The midpoint between both fingers represents the focal pivot point around which both pan translation and zoom scaling occur simultaneously in real time.

Why do stroke widths become huge or tiny when zooming into an SVG?

By default, SVG stroke widths scale proportionally with the coordinate matrix. When you zoom in by 5x, a 2px stroke renders as 10px on screen. To maintain a constant visual pixel stroke width regardless of zoom level, apply the CSS property 'vector-effect: non-scaling-stroke;' to all paths, circles, and rect elements.

How does screenToSVG coordinate conversion handle high-DPI (Retina) displays?

Native SVG DOM methods like svg.getScreenCTM() automatically account for window.devicePixelRatio, CSS transforms on parent containers, page scroll offsets, and viewport margins. By creating an SVGPoint via svg.createSVGPoint() and multiplying it by getScreenCTM().inverse(), you obtain pixel-perfect SVG user coordinates regardless of display scaling or device pixel ratios.

Can you implement smooth inertia momentum scrolling with SVG pan and zoom?

Yes. By calculating pointer velocity (distance traveled divided by elapsed time between pointermove events), you can initiate a requestAnimationFrame physics decay loop upon pointerup. The velocity decays each frame by a friction multiplier (typically 0.92 to 0.95) until the displacement falls below a subpixel threshold, creating an iOS-like fluid panning experience.
