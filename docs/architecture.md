## 2. Target System Architecture (v2)

### 2.1 Technology Stack

| Layer | Technology | Rationale |
|---|---|---|
| **Site Framework** | **Astro 5** (`output: 'static'`, `<ClientRouter />` View Transitions) | Zero-JS static HTML for all editorial, hub, comparison, and docs pages; clean island hydration for the interactive icon explorer. |
| **Interactive UI** | **Svelte 5** (Runes: `$state`, `$derived`, `$effect`, `$props`) | Fine-grained reactivity with minimal runtime (~10–15 KB gzip), zero virtual DOM diffing overhead on grid scroll. |
| **Styling** | **Tailwind CSS v4** (`@tailwindcss/vite`, `@theme` design tokens) | Zero-runtime CSS with native CSS custom properties driving live grid icon color, stroke, and size updates without JS re-renders. |
| **Grid Virtualization** | **`@tanstack/svelte-virtual`** (`createVirtualizer`) | Windowed row virtualization capping mounted icon DOM tiles at **`<= 180`** regardless of whether 50 or 134,701 icons match. |
| **Search Engine** | **Dedicated `search.worker.ts`** over binary typed-array index | `< 15 ms` P95 search & multi-facet bitmask filtering across all 134,701 icons in `~8 MB` worker RAM; zero Fuse.js, zero full-object cloning. |
| **Export Engine** | **Dedicated `export.worker.ts`** (`OffscreenCanvas` + `fflate`) | Off-main-thread PNG rasterization, SVG/JSX/Vue/Svelte/CSS codegen, and streaming ZIP archives with Transferable buffers. |
| **Client Persistence** | **IndexedDB (`iconstash-v2`)** + **Bounded RAM LRU Cache** | Persists fetched `/chunks/v1/{library}.json` shards locally while capping in-memory hydrated chunks to **4–6 chunks (`<= 28 MB`)**. |
| **Offline & Asset Cache** | **Minimal Service Worker (`sw.js`)** | Precaches hashed Astro app shell + binary search index only. **Explicitly excludes `/chunks/v1/*`** (owned by IndexedDB) to eliminate double storage. |

### 2.2 High-Level Data Flow

```text
[Build Time]
data/*.json (28 master files, 140 MB)
   ├──► scripts/build-chunks.mjs ──► public/chunks/v1/{library}.json (compact, build-normalized SVGs)
   │                                  public/chunks/v1/manifest.json
   ├──► scripts/build-search-index.mjs ──► public/index/v1/search.bin (~4.5 MB raw / ~1.8 MB br)
   │                                        public/index/v1/search-meta.json
   ├──► scripts/generate-api.js ──► public/api/v1/* + public/data/{slug}.json (SDK/MCP compat)
   ├──► astro build ──► dist/ (MPA shell, Svelte 5 islands, editorial, hubs, compare)
   └──► scripts/generate-icon-pages.mjs --tarball ──► release/icons-pages.tar.zst (134.7k+ pages + sitemaps)

[Browser Runtime]
Astro Page Load (0-JS shell + SSR top viewport)
   ├──► Main Thread (Svelte 5 Islands)
   │      ├── VirtualIconGrid (@tanstack/svelte-virtual, <= 180 DOM tiles)
   │      ├── ChunkLRUCache (RAM: max 4–6 chunks <= 28 MB) ◄──► IndexedDB (iconstash-v2) ◄──► /chunks/v1/*.json
   │      └── CSS Custom Properties (--ic-color, --ic-stroke-width, --ic-size) -> 0 re-renders
   ├──► search.worker.ts (Singleton across View Transitions)
   │      └── Loads /index/v1/search.bin (~8 MB RAM) ──► returns Transferable Uint32Array of iconIndices
   └──► export.worker.ts (Lazy-spawned on export)
          └── OffscreenCanvas PNG + fflate ZIP ──► returns Blob / Transferable ArrayBuffer
```

### 3.2 Island Communication & State Architecture

- **No prop-drilling across islands.** Shared interactive state lives in Svelte 5 `.svelte.ts` rune modules under `src/lib/state/`:
  - `explorer.svelte.ts`: active query, selected library bitmask (`number`, 28 bits), category bitmask (`number`, 16 bits), style bitmask (`number`, 7 bits), sort mode, `resultIndices: Uint32Array` (from search worker), `totalMatches: number`.
  - `preview.svelte.ts`: color, strokeWidth, iconSize, density (`compact` | `default` | `comfortable`), theme — writes CSS variables directly to `:root` / grid container.
  - `inspector.svelte.ts`: `activeIconIndex: number | null`, pinned icon payload, gradient/filter/motion options (isolated strictly to the inspector SVG).
  - `collections.svelte.ts`: `localStorage`-backed named collections (`Set<string>` of icon IDs) + multi-select bulk tray.
- **Persistent Worker Singletons:** `search.worker.ts` is attached to `globalThis.__ICONSTASH_SEARCH_WORKER__` so Astro View Transitions (`<ClientRouter />`) between `/` and `/library/lucide/` reuse the already-loaded binary search index without re-fetching or re-initializing.

## 4. Sharded Per-Library Chunk Schema (`/chunks/v1/{library}.json`)

### 4.1 Design Goals

1. **Eliminate repeated per-icon boilerplate:** Hoist `library`, `librarySlug`, `libraryVersion`, `npmPackage`, `license`, `attributionRequired`, `docsUrlBase`, `defaultViewBox`, and `defaultStrokeWidth` to the file header.
2. **Build-time SVG normalization:** Normalize `fill`/`stroke` attributes to `currentColor` and strip redundant inline `stroke-width` overrides at build time (eliminating `icons.js:21-34`'s runtime regex + `_normalizedBody` memory doubling).
3. **Mega-library sub-sharding:** Libraries with `<= 8,000` icons emit a single `/chunks/v1/{library}.json` (23 of 28 libraries). The 5 libraries exceeding 8,000 icons (`fluent` 20,170; `materialsymbols` 18,547; `materialsymbolslight` 15,969; `material` 14,001; `phosphor` 9,198) are split into deterministic **4,000-icon sub-shards** (`/chunks/v1/{library}-{0..N}.json`, each `~1.8–3.5 MB` raw / `~300–550 KB` gzip) referenced in `/chunks/v1/manifest.json`, ensuring every individual chunk fetch stays under `~4 MB` raw and fits cleanly inside the 4–6 chunk LRU RAM budget.

### 4.2 Exact Chunk JSON Schema (`/chunks/v1/{library}.json` or `{library}-{part}.json`)

```json
{
  "schemaVersion": 1,
  "librarySlug": "lucide",
  "libraryName": "Lucide",
  "libraryId": 0,
  "version": "0.468.0",
  "license": "ISC",
  "attributionRequired": false,
  "npmPackage": "lucide",
  "docsUrlBase": "https://lucide.dev/icons/",
  "defaultViewBox": "0 0 24 24",
  "defaultStrokeWidth": 2,
  "part": 0,
  "totalParts": 1,
  "startIndex": 0,
  "count": 1979,
  "viewBoxes": ["0 0 24 24"],
  "icons": [
    [
      "a-arrow-down",
      "<path fill=\"none\" stroke=\"currentColor\" stroke-linecap=\"round\" stroke-linejoin=\"round\" d=\"m14 12l4 4l4-4m-4 4V7M2 16l4.039-9.69a.5.5 0 0 1 .923 0L11 16m-7.696-3h6.392\"/>",
      0,

```

#### Tuple Layout (`icons[localOffset]`)

Each icon entry is a 5-element positional tuple (zero repeated property keys):

| Index | Field | Type | Description |
|---:|---|---|---|
| `0` | `name` | `string` | Canonical icon name (`id` is deterministically `${librarySlug}-${name}` unless overridden in optional `idOverrides` map). |
| `1` | `svgBody` | `string` | Build-time normalized inner SVG markup (`currentColor`, no outer `<svg>`, no redundant `stroke-width` on outline paths so CSS variables apply cleanly). |
| `2` | `viewBoxIdx` | `number` | Index into the chunk's `viewBoxes[]` table (`0` for >99% of icons). |
| `3` | `strokeWidth` | `number` | `0` for filled/solid icons; `1 | 1.5 | 2` for stroke icons. |
| `4` | `flags` | `number` | Bitmask: `bit 0` = isFilled (`fill="currentColor"`), `bit 1` = hasVariants, `bit 2` = hasAnimatedElements (`linemd`). |

*(Metadata like `category`, `style`, `tags`, and global `iconIndex` live in the binary search index and are never duplicated in the SVG chunk, cutting raw chunk sizes by ~52% across the catalog: 140 MB -> ~68 MB raw across all 28 libraries.)*

```json
{
  "schemaVersion": 1,
```

## 5. Compact Typed-Array Search Index Schema (`/index/v1/search.bin`)

To eliminate Fuse.js (~250 MB RAM) and `postMessage` full-object cloning (~300 MB RAM), the build pipeline compiles a single binary file `/index/v1/search.bin` (~4.5–5.5 MB uncompressed, ~1.7–2.1 MB Brotli/Gzip) plus a tiny `/index/v1/search-meta.json` (~4 KB) containing the 28 library labels, 16 category names, and 7 style names.

### 5.1 Binary Layout (`search.bin`, Little-Endian)

```text
Offset   Size (bytes)           Section
────────────────────────────────────────────────────────────────────────────
0x0000   64                     Header (magic, version, counts, section offsets)
0x0040   N * 4                  metaPacked: Uint32Array[N] (bit-packed facets)
...      (N + 1) * 4            nameOffsets: Uint32Array[N + 1] (byte offsets into nameBuf)
...      nameBufBytes           nameBuf: Uint8Array (concatenated lowercase UTF-8 names)
...      (V + 1) * 4            vocabOffsets: Uint32Array[V + 1] (10,849 unique tokens)
...      vocabBufBytes          vocabBuf: Uint8Array (sorted lowercase UTF-8 token strings)
...      (V + 1) * 4            postingsOffsets: Uint32Array[V + 1] (element offsets)
...      P * 4                  postingsIds: Uint32Array[P] (sorted iconIndex postings + match-type bit)
...      C * 4                  conceptBuckets: optional cross-library baseName hash table
```

#### Header Specification (64 bytes)

| Byte Offset | Type | Field | Value / Description |
|---:|---|---|---|
| `0..3` | `char[4]` | `magic` | `"ICS2"` (`0x32534349`) |
| `4..5` | `uint16` | `version` | `1` |
| `6..7` | `uint16` | `flags` | Reserved (`0`) |
| `8..11` | `uint32` | `iconCount` | `134701` (`N`) |
| `12..15` | `uint32` | `vocabCount` | `~10849` (`V`, union of name tokens + tag tokens) |
| `16..19` | `uint32` | `postingsCount` | `~950000` (`P`, deduplicated `(token, iconIndex)` pairs) |
| `20..23` | `uint32` | `offMetaPacked` | Byte offset of `Uint32Array[N]` |
| `24..27` | `uint32` | `offNameOffsets` | Byte offset of `Uint32Array[N + 1]` |
| `28..31` | `uint32` | `offNameBuf` | Byte offset of `Uint8Array` (padded to 4-byte boundary) |
| `32..35` | `uint32` | `offVocabOffsets` | Byte offset of `Uint32Array[V + 1]` |
| `36..39` | `uint32` | `offVocabBuf` | Byte offset of `Uint8Array` (padded to 4-byte boundary) |
| `40..43` | `uint32` | `offPostingsOffsets` | Byte offset of `Uint32Array[V + 1]` |
| `44..47` | `uint32` | `offPostingsIds` | Byte offset of `Uint32Array[P]` |
| `48..63` | `uint8[16]` | `reserved` | Zero-padded (4-byte aligned) |

#### Per-Icon Bit-Packed Metadata (`metaPacked[iconIndex]`, 32 bits)

| Bits | Width | Field | Range |
|---|---:|---|---|
| `0..4` | 5 bits | `libId` | `0..27` (28 libraries) |
| `5..8` | 4 bits | `catId` | `0..15` (16 categories) |
| `9..11` | 3 bits | `styleId` | `0..6` (7 styles) |
| `12..13` | 2 bits | `strokeIdx` | `0..3` (`[0, 1, 1.5, 2]`) |
| `14` | 1 bit | `isFilled` | `0` = outline, `1` = fill/solid/bold |
| `15` | 1 bit | `hasVariants` | `0/1` |
| `16..31` | 16 bits | `rankScore` | `0..65535` (deterministic tie-breaker / tier weight) |

#### Posting Entry Encoding (`postingsIds[k]`, 32 bits)

- Bits `0..23` (`iconIndex & 0x00FFFFFF`): supports up to `16,777,215` icons.
- Bits `24..27` (`matchWeight`): `4` = exact name token, `2` = name prefix/sub-token, `1` = tag/synonym match.
- Bits `28..31`: reserved.

### 5.2 Query Execution & Memory Footprint

- **Facet-only filter (empty query):** Single linear pass over `metaPacked[0..134700]` checking `((1 << libId) & libMask) !== 0 && ((1 << catId) & catMask) !== 0 && ((1 << styleId) & styleMask) !== 0`. Takes **`< 1.2 ms`** in V8.
- **Keyword + facet query:**
  1. Tokenize query into lowercase terms (`qTokens`).
  2. Binary-search `vocabOffsets`/`vocabBuf` for exact + prefix range of each token (`O(log V)`).
  3. Accumulate scores into a reusable pre-allocated `Uint16Array(N)` scratch buffer (`269 KB`, zero GC allocations per keystroke!), tracking touched indices in a reusable `Uint32Array(N)` buffer (`538 KB`).
  4. Apply `libMask`/`catMask`/`styleMask` via `metaPacked[idx]` and sort top matches.
  5. Copy matched `iconIndex` slice into a compact `Uint32Array` and **transfer** its `ArrayBuffer` (`postMessage(msg, [ids.buffer])`) to the main thread.
- **Total Worker RAM:** `~5.5 MB` (`search.bin` `ArrayBuffer`) + `~0.8 MB` reusable scratch buffers + `~1.5 MB` JS runtime overhead = **`~7.8 MB` total** (down from ~450–600 MB).

## 6. Web Worker Message Protocols

### 6.1 Search Worker (`src/workers/search.worker.ts`)

```ts
// Main Thread -> Search Worker
export type SearchWorkerRequest =
  | { type: 'INIT'; indexUrl: string; metaUrl: string }
  | {
      type: 'QUERY';
      queryId: number;
      query: string;
      libMask: number;     // 28-bit bitmask (0 = all libraries)
      catMask: number;     // 16-bit bitmask (0 = all categories)
      styleMask: number;   // 7-bit bitmask  (0 = all styles)
      sort: 'relevance' | 'az' | 'za' | 'library';
      limit?: number;      // 0 = return all matching indices (default)
    }
  | { type: 'CONCEPT_MATCHES'; queryId: number; iconIndex: number; maxPerLibrary?: number }
  | { type: 'CANCEL'; queryId: number };

// Search Worker -> Main Thread
export type SearchWorkerResponse =
  | { type: 'READY'; iconCount: number; indexBytes: number; initMs: number }
  | {
      type: 'RESULTS';
      queryId: number;
      indices: Uint32Array;       // Transferred buffer (zero-copy)
      totalMatches: number;
      elapsedMs: number;
      libraryCounts: Uint32Array; // 28-element facet counts (transferred)
    }
  | {
      type: 'CONCEPT_MATCHES';
      queryId: number;
      indices: Uint32Array;       // Cross-library matching iconIndices (transferred)
    }
  | { type: 'ERROR'; queryId?: number; message: string };
```

## 7. Standalone Streaming 134k+ Icon HTML + `--tarball` Generator

### 7.1 Why Separate from `astro build`

Running 134,701+ icon routes and 3,746 concept hub routes through Astro/Vite's SSG pipeline would require loading 138k+ virtual modules into Rollup, causing multi-GB Node heap spikes and 30+ minute builds. Instead:

- **`astro build`** builds the core site (~360 routes: Explorer, libraries, categories, styles, articles, glossaries, listicles, comparisons, alternatives, frameworks, legal/API docs) in `< 20 seconds`.
- **`scripts/generate-icon-pages.mjs`** runs **after** `astro build`, extracts the exact hashed CSS `<link>` and header/footer chrome from `dist/`, and streams all `134,701` icon pages + `3,746` concept pages + XML sitemaps in `< 25 seconds` using `< 120 MB` Node RSS.

### 7.2 Streaming Pipeline Architecture

1. **Pass 1 — Lightweight Concept Index (`< 45 MB` Node RSS):**
   - Streams `public/chunks/v1/manifest.json` and `public/index/v1/search.bin` (or iterates library JSONs extracting only `{ id, name, baseName, librarySlug, category, style }`) to compute canonical URLs, related icons, and cross-library concept groups (`CONCEPT_MIN_LIBRARIES = 3`).
2. **Pass 2 — Library-by-Library HTML Streaming (`< 80 MB` Node RSS):**
   - Loads **one library** at a time from `public/chunks/v1/{library}*.json`.
   - Renders each icon's HTML string via a pure template function (zero DOM/JSDOM, zero Handlebars overhead), embedding the normalized `<svg>`, JSON-LD (`ImageObject` + `BreadcrumbList`), cross-library comparison links, and a `< 3 KB` shared `/assets/icon-page.js` interactive enhancer.
   - Releases the library array for GC before moving to the next library.
3. **Output Modes:**
   - **`--out <dir>`** (default `./dist/icons`): Bounded concurrency writer (64 concurrent `fs.promises.writeFile` handles) for local verification or rsync.
   - **`--tarball <file>`** (e.g., `./release/iconstash-icons.tar.zst` or `.tar.gz`): Writes POSIX USTAR tar headers + UTF-8 HTML buffers **directly into a streaming `tar-stream` -> `zstd`/`zlib.createGzip()` pipeline**. Zero intermediate files on disk, zero inode exhaustion on CI runners, atomic server-side extraction (`tar --zstd -xf iconstash-icons.tar.zst -C /var/www/iconstash`).
   - **`--limit <N>`**: Smoke-test mode (e.g. `--limit 500`) for fast CI validation of HTML structure, JSON-LD validity, and canonical links.
4. **Sitemaps & Legacy Redirects:**
   - Streams `sitemaps/sitemap-1.xml`, `sitemap-2.xml`, `sitemap-3.xml` (max 50,000 URLs each), `sitemaps/concepts.xml`, and root `sitemap.xml` index concurrently during Pass 2.
   - Replaces the 14,915 individual `icons/{retired-slug}/index.php` stub directories with a single Apache `ErrorDocument` / compact PHP lookup map (`icons/redirect-map.php` backed by a sorted binary/JSON map) so zero retired URLs lose 301 equity without polluting the filesystem with 15k extra directories.
